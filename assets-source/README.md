# 北京地标资产

当前有 29 个模型源文件、32 个地理位置。主尺寸依据与未核验项逐个记在 `landmarks/<id>.json`；67 张逐文件照片的作者、日期、角度、许可保存在 `../refs/open-photo-index.json`，31个位置至少有两份对应文件；箭楼的两份误名照片经实际查看确认都是正阳门城楼，已纠正归属，箭楼目前没有有效对象照片。逐立面像素与摄影标定仍未完成。发布汇总在 `../public/models/landmarks/references.json`。OSM 几何为 WGS84，坐标原点保持北纬 39.9475、东经 116.41。模型单位为米；Blender X 向东、Y 向北、Z 向上，导出 glTF 时转换为 Y 向上。地形基准采用数据管线相对 45m 参考高程的采样值，运行时可由实际地形采样替换。

这批模型是建筑形制与 OSM 平面校准的重建。公开单张照片不是连续摄影测量数据，未经过独立控制点测量，不能宣称厘米或 3m 位置精度。屋面形制、殿身尺度与已核验高度使用官方资料；未核验的斗拱、彩画、雕刻、室内、附属构件和立面高度仍为近似。月坛只重建已经映射的钟楼与庭院建筑，没有臆造缺少可靠位置资料的祭坛。

## 可复现构建

安装项目开发依赖，提供 Blender 5.x（`BLENDER_BIN` 可指定路径）和 KTX Software `toktx`（`TOKTX` 可指定绝对路径），然后运行：

```
node scripts/models-build.mjs
```

构建读取已保存的 `raw/geospatial/osm.geojson` 和 `landmark-elevations.json`，无需联网或新账户。`models-parks` 和 `models-registry` 生成单一注册表；Blender 生成 near 原网格及省去小构件的 coarse 网格；`models_lods` 从干净的源 blend 导出 medium、far、collision，保持原模型地面基准与高度包络。园区碰撞使用按单体建筑 footprint 的实体代理；门楼保留真实券洞。未达到纹理或几何条件时校验失败，不把占位模型当成成功产物。

`toktx` 官方工具版本为 Khronos KTX Software 4.4.2：<https://github.com/KhronosGroup/KTX-Software/releases/tag/v4.4.2>。Apple Silicon 使用 Darwin-arm64 安装包中的工具；Linux/Windows 使用对应官方发行包。项目的本地 `tools/bin` 只是开发机工具位置，不发布二进制也不要求写系统目录。Basis transcoder 位于 `public/decoders/basis`，按上游 Apache-2.0 发布并附完整许可与NOTICE；目录另保留 Three.js 包装代码的 MIT 许可，二者不能混称。

## 纹理与优化

`textures` 保留 22 组 Cycles 实际烘焙的 512×512 baseColor、tangent normal、roughness PNG；原 procedural 节点经过烘焙后由标准 Principled image 节点替换，图片打包进源 blend 与 GLB。原照片像素未贴入产品。材质代表常见的釉瓦、灰砖、红木、白石、钢材和玻璃，不冒充历史建筑彩画扫描。

发布 GLB 采用 Meshopt 网格压缩和 KTX2 mipmap 图片（baseColor/ORM 为 ETC1S，normal 为 UASTC）。同一纹理只压缩一次，重建缓存放在 `artifacts/model-texture-cache`，不纳入发布与版本历史。`models-fingerprint` 为每个 GLB 生成内容哈希 URL，让浏览器缓存随资产变更更新。国贸塔体保留已经极简的 28 三角面轮廓；水立方的泡格外壳仍是 12 三角面，另增加凹入玻璃底层、白柱与窗框，几何细节随距离简化。

`models-validate` 使用 Khronos glTF Validator 与 glTF Transform 实际解码所有发布 GLB，检查几何、米制尺寸、地面基准、PBR 图片与 LOD 复杂度。当前 Validator 对 KHR_texture_basisu 的支持有限，其扩展/ MIME 警告单独记录；KTX2 的签名、尺寸、mipmap 另作实际检查，浏览器截图验证实际转码。报告写在 `tests/reports/models.json`。固定源模型预览在 `previews`，并保存相机位置、尺度、光照和渲染参数；应用内固定地理镜头由主项目截图验证覆盖。

`node scripts/models-dimensions.mjs` 只读解码最终三处样板的 near GLB，按连通构件与实际顶点测量，独立官方数值写在校核脚本，报告在 `../tests/reports/model-dimensions.json`，不使用注册表高度自证。祈年殿采用北京市公园管理中心详细构件口径：下/中/上台基直径 90.3/79.3/68.2m、台高 5.2m、台上殿高 31.6m、通高 36.8m；中央四柱 19.2m 高、1.2m 直径。官方另有“约38m”及台高6m的概述，记录为口径冲突，没有把两者伪称同一精确测量。台基与殿身分别建构，没有把整殿等比拉伸来纠正高度。

太和殿主柱轴网接近 63.96×37.17m，但现有文本没有明确长宽是否以柱轴或外皮测量，报告同时列出柱外缘尺寸，保留端点定义未核验。CCTV 的 234m 总高已按实际包络核对；75m 自由悬挑的支持面/终点尚无独立匹配，不以整段上部体块76m代替。祈年殿所述32m直径的精确屋缘边界也没有图纸校准。13个定义明确的样板尺度在2%以内，不等于整座建筑或全部32位置已达实测验收；各位置缺少独立地面控制点，3m位置精度仍未验收。

鸟巢经设计方屋顶平面与两剖面实际像素查看后，补齐连续马鞍形环状屋面、椭圆洞口、ETFE/PTFE两层膜、24个主支撑、1.2m宽矩形钢构及非规则次钢件；三层看台使用窄踏步和立面，东西最高约51m、南北约45m。185.3×127.5m洞口与110×72m草坪通过最终GLB实际顶点核对，各LOD中央洞口都有32处采样确认不被膜封住；报告在 `../tests/reports/model-olympic-dimensions.json`。屋面细杆线路、节点、看台排数和颜色分布仍为合理推断。官网333×296×69m、论文332.3×296.4×68.5m与保留333×294×69m口径不同，逐项记录，未伪称完全一致。鸟巢碰撞单独使用1324三角面的环状屋面/看台/24主支撑代理，保留洞口和开放外墙，不把10万面渲染网格送入行走碰撞。

水立方保持177×177×31m，独有ETFE材质重烘米级泡格、浅蓝色差、接缝和鼓起法线；两张开放照片的实际像素对照还确认其底层有凹入玻璃入口和白柱，模型现补齐该层。4.2m层高、1.8m凹入、12m柱距及未展示立面的连续布置为明确推断，没有冒称实测。32m贴图周期约6格，即代表尺度约5.3m，兼顾近景可辨识与手机成本。Arup工程师文章确认约4000个气枕、部分跨度达9m、屋顶7种/墙15种重复组合；本次原创Voronoi近似没有声称精确还原这些Weaire–Phelan竣工排布、真实鼓起深度或严格3–7m范围。新源预览为 `previews/watercube.png`，far仍用均色材质。建筑膜的光学透射以性能友好的PBR外观近似，未经光学参数实测。

## 许可边界

逐文件 CC 照片可以依其作者、许可与修改标注条件再使用；CC BY-SA 衍生贴图应保留相容许可。官方照片与建筑平面 PDF 仅作参考，未确认其再分发许可。现有来源不明的 `refs/qiniandian1.jpg`、`qiniandian2.jpg`、`taihedian1.jpg` 保留作历史参考，不进入发布纹理。OSM 派生几何保留 OpenStreetMap contributors 与 ODbL 归属。原创模型、烘焙材质的分发政策由项目所有者决定；这份文档没有替项目改许可证。

CCTV 两张开放照片已经实际查看，确认钢网在倾斜塔体、悬挑外侧与底面连续；源模型补齐四侧代表性网格及悬挑/底面网格，上下疏密随之变化。具体杆件走向、密度与截面未取得竣工CAD，属于代表性重建，悬挑底面的圆窗及精确入口细节仍未重建。两处更新的查看范围在对应 `landmarks` 清单及 `../docs/landmark-visual-review.md` 中记录；目录索引的其余照片不能据此视为已查看。

传统门楼的已取得照片经实际查看后，定向补齐永定门/鼓楼三檐、永定门灰砖与鼓楼红台基、神武门三通洞、午门北五口/南三口及侧向曲门、钟楼双灰绿檐与灰砖钟室的中央大拱和凹入关闭侧小拱。午门两侧通道转入U翼内院，真实口数有照片依据，7m洞宽与90°转弯线路属于明确推断。钟楼24m台基、24.8m上层地板及拱室各部分比例也未实测。原注册总高和地理落位保持不变。`../tests/reports/model-gates.json` 直接解码 near/medium/collision：测量大屋面连通分量、双向门洞射线及实际材质槽/嵌入KTX2哈希；预览只证明源结构，应用最终GPU图仍由整站验收负责。两个误名箭楼文件均实际画正阳门城楼，已转移归属；箭楼有效照片0，不以元数据标题冒充核验。
# 本轮可得像素资料后的最后主体修正

本轮现代/园区 30 张与传统 17 张已取得照片均已实际查看，逐张可见范围、作者、许可与未核验项目见 `../docs/landmark-visual-review.md` 及 `../artifacts/model-references/visual-review.json`。照片只有局部可见形制依据，不是连续摄影测量或 3m 测量验收；施工态、牌坊/阶梯和误名城楼照片不作为对应主殿的完整立面证明。

定向纠正辟雍的重檐攒尖与圆顶饰、月坛已映射钟楼的双绿檐/红砌体/贯通拱洞、玲珑塔白色外框及斜撑、奥林匹克塔冠底树枝承托与塔间跨接，以及正阳门灰砖台基。钢构采用代表性枝干/外框，尺寸、路线、节点和未展示立面明确为推断，不宣称逐杆竣工复制。仅这 5 个模型重新导出；其余 24 个模型的 96 份唯一 GLB 以 SHA256 校核不变，32 处注册的高度/位置/足迹/旋转/地形高程未变。

`models-form-validate.mjs` 在最终解码 GLB 中检查两层独立大屋面、月坛三等级实际拱洞射线、正阳门台基实际灰砖命中、玲珑四高度外框截面/斜边、奥塔五冠下展开钢枝与跨塔构件。该脚本与既有几何/尺寸/奥园/立面/门楼门禁均加入 `check:models` 和生产入口。玲珑远级专用 `.35` 简化比例同时落实在源导出与 LOD 导出，避免小模型旧分支导致远级面数高于中级。
