# 北京世界 · Beijing World — 3D 虚拟仿真北京

## 目标
复刻 Matt Shumer "Manhattan World" 的效果，做北京版：**一个公开网页链接里的可交互 3D 虚拟北京**（Three.js 网页版）+ **一段电影级漫游视频 MP4**（对应帖子中的曼哈顿视频）。全部使用免费公开数据（OpenStreetMap，ODbL 许可，页面带署名）。

## 已确认的三个选择
- **覆盖范围**：全明星套餐 — 二环老城（故宫/天安门/中轴线/什刹海/天坛）+ 国贸CBD（中国尊/央视大楼）+ 奥林匹克公园（鸟巢/水立方），约 12×10 km
- **视觉风格**：电影感写实 — 黄昏金色光照+大气雾+bloom，内置白天/夜景切换
- **部署方式**：GitHub Pages（回退：Netlify 手动上传）

## 技术方案

**技术栈**：Vite + TypeScript + Three.js（纯静态站点），数据构建期烘焙，页面运行时零 API 依赖。

**1. 数据管线（Node 构建脚本，一次性执行）**
- 用 Overpass API 下载北京 bbox（约 39.83–40.05°N, 116.33–116.50°E）：建筑轮廓（含 height/building:levels）、道路网分级、水系（护城河/什刹海/北海/通惠河）、绿地公园、铁路地铁线
- 处理打包为紧凑二进制（.bin：建筑足迹顶点 + 高度 + 颜色分类 + 道路折线 + 水面/绿地多边形），作为静态文件随页面加载
- 高度策略：height 标签 > building:levels×3.3m > 按类型默认（胡同平房~7m、多层~20m、高层~60m）；地标建筑手工写入公开高度（中国尊 528m、国贸三期 330m、央视大楼 234m 等）

**2. 渲染（Three.js，目标 20 万+建筑 60fps）**
- 合并几何 + InstancedMesh 批量渲染建筑；道路网（环路立交简化造型）、水面反射、公园 + 实例化树木
- **地标程序化建模**（代码建模，曼哈顿效果的关键）：故宫建筑群（红墙金顶）、天坛祈年殿、天安门、正阳门、钟鼓楼、雍和宫、中国尊（收分花瓶轮廓）、央视总部（悬挑立体环）、鸟巢（编织网壳）、水立方（气枕方盒）、国家大剧院（银色巨蛋）、奥林匹克塔
- 电影级氛围：黄昏金色光照 + 大气雾 + 泛光 bloom；**夜景模式**（楼体点灯、道路车流光带）
- **相机四模式**：① 自动电影漫游（沿中轴线：永定门→前门→天安门→故宫→景山→鼓楼→奥园，再切 CBD 天际线）② 自由飞行 ③ 第一人称街景 ④ 点击地标自动飞行 + 中英文标签
- UI：标题「北京世界 · Beijing World」、加载进度条、模式/昼夜切换、OSM 署名

**3. 视频生成**
- Puppeteer + headless Chrome 沿确定性相机路径逐帧截屏 → ffmpeg-static（npm 包，免 brew 安装）编码 **1080p/60fps、约 60–90 秒 MP4**，地标字幕淡入，页面提供视频下载

**4. 公开部署**
- 默认：构建产物推送到你 GitHub 的新仓库并开启 GitHub Pages；若推送鉴权不可用 → 回退给你 zip + Netlify Drop 网页拖拽上传指引（同样免费得公开链接）

## 实施步骤
1. 初始化 Vite + TS + Three 项目骨架
2. 数据管线：分块下载 Overpass → 解析 → 烘焙二进制（输出数据质量统计）
3. 核心渲染：地面/建筑/道路/水系/绿地
4. 地标程序化建模
5. 光照、夜景与后期
6. 相机系统与 UI
7. 性能优化（合并/实例化/视锥剔除，本机实测帧率）
8. 视频逐帧渲染 → MP4
9. 部署 GitHub Pages 公开链接，交付：**公开 URL + MP4 视频 + 源码**

## 风险与对策
- Overpass 大范围下载超时 → 分块请求 + 镜像重试
- 部分建筑无高度 → 类型默认值 + 地标手工数据
- 帧率不足 → 合并几何/实例化/LOD 三级优化
- GitHub 推送需登录授权 → 回退 Netlify 手动上传
