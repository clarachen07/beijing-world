# 北京世界：实现与数据生产

网站继续使用 Three.js 0.180、TypeScript 与 Vite。网站构建仅消费已验证静态资产，不访问 Overpass、不下载地理数据、不启动 Blender。

## 运行时

`main.ts` 管启动、生命周期、环境与模块接线；`ui.ts` 管可触达控制、标签避让与反馈；`controls.ts` 是相机状态的唯一所有者，包含鸟瞰、飞行、漫游、步行和可中断过渡。失焦、隐藏、触控取消清空输入，显式捕获帧采用绝对时间，恢复时完整接回位姿。

`tiles.ts` 按视锥与屏幕误差选择 8km / 2km / 500m 层级。子块未齐时显示父块，避免叠加与空洞；首次只等待故宫附近远景。`asset-fetch.ts` 为模型、城市、纹理共用最多六个完整响应体下载，支持优先级、取消与超时。`loader.ts` 将压缩网格交给 Worker 解码；主线程按帧组装。

`city.ts` 共用材质，地表纹理以引用计数管理；近区树点按细节档显示。离开视野超过15秒的城市几何与纹理释放，另设数量/内存预算。`collision.ts` 只登记附近已加载500m块与地标代理，以 Octree/Capsule 检查步行和安全落点；未知地面不能进入。`legacy.ts` 负责地标下载、解析、细节档及碰撞代理，其他模块不重复登记同一地标。

`traffic.ts` 在固定种子与绝对秒数下计算车辆；环境和相机捕获按帧编号求值，不累计逐帧副作用。`effects.ts` 根据帧间隔调整像素比与后期质量，桌面 MSAA、移动 FXAA。视频生成使用同一捕获接口，产物目录独立于发布目录。

## 坐标和数据

唯一配置位于 `config/world.json`；经纬度使用 WGS84，本地米坐标 x向东、z向南、y向上。采用北京纬度处固定比例的局部投影，因此它不是测绘控制网。地面 y 为处理后的 Copernicus DSM 相对45米参考海拔；建筑相对高度叠加地面，地标、交通与碰撞共用采样基准。

四环边界来自 OSM 真实主路节点连接闭环，原始节点/way编号和检查报告保留。正式区域为闭环内，加500米视觉缓冲和奥园扩展。Overture 是轮廓底座，OSM 匹配补属性，重叠与精修地标替代建筑剔除；部件、内洞、最小架空高度保留。普通建筑缺失高度时逐要素记录推断，绝不补造随机建筑轮廓。

免费官方 Overture z14 / extent4096 矢量瓦片在北京有约0.46米编码网格；它不等于实测位置精度，瓦片简化也不等于原始 GeoParquet。10米 Sentinel 影像只提供远景地表色；经过滤波的30米DSM不能作为步行级测量真值。来源索引与官方快照日期随发布数据保存。

## 资源版本与故障

城市二进制、影像以内容哈希命名；分片下载和烘焙完整性独立验证。构建生成资源清单、来源页面与代码/数据/模型共同派生的发布版本。Service Worker 每版本一个缓存，更新时不会继续取旧模型；只缓存成功完整响应，视频不进入资源缓存。国内资源根地址可通过 `VITE_ASSET_BASE` 配置。源码提交镜像仅在干净提交或明确指定 `VITE_SOURCE_SHA` 时启用，路径包含 `public`。

初始资源失败提供重新载入；部分分块/模型失败保留已成功远景或占位，提供重试；页面隐藏暂停模拟；WebGL上下文丢失暂停输入，恢复后重新编译画面。缓存只支持访问过的区域离线，不会预装全城。

## 文件边界

- `src/`：运行时代码；`config/`：世界及唯一地标注册表。
- `scripts/`：数据生产、发布、来源生成与通用验证。
- `blender/`：可复现建模脚本；`assets-source/`：米制 Blender 源文件和原创材质。
- `refs/`：实景参考及许可；`raw/`：本地数据快照，忽略于网站和 Git。
- `public/data/`、`public/models/`、`public/decoders/`：网站需要的静态资源。
- `tests/`：行为测试与资产验证记录；`artifacts/qa/`：截图、性能和浏览器结果。
- `artifacts/history/`：保留的历史诊断与来源不明图片；`artifacts/video/`：可重建帧和编码临时文件。
- `.deployment/gh-pages/`：从旧 `dist/` 迁出的独立部署仓库，历史和远端一致；常规构建不会操作它。

## 验证入口

`npm run check` 执行类型、Node行为测试、资源完整性、模型检查和生产构建。`npm run check:data` 用独立数据环境验证真实闭环和地理数据；`npm run check:browser` 验证实际输入与恢复；`npm run check:performance` 记录12个固定镜头、3分钟路线、20次已预热区域往返后16.5秒清理和确定性，未把预热往返冒充20次完整冷卸载/重载。设备、网络模拟及未完成实机测试在验收报告中分别记录。
