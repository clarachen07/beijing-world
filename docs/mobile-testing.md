# 手机实测

`qa.html` 是独立测试入口，与主产品界面分开。它加载同源 `index.html`，使用项目现有的场景、相机和性能指标；不会上传结果，不加载额外依赖，也不创建另一张 WebGL 画布。

## 在真实手机打开

使用已有最新发布构建启动预览：

```sh
npm run preview -- --host 0.0.0.0
```

手机和电脑连接同一局域网，在手机浏览器打开：

```text
http://电脑局域网IP:4173/qa.html
```

电脑防火墙需允许该连接。请使用电脑的局域网 IP，手机上的 `localhost` 指向手机自身。测试页属于 `public`，需包含在最新发布构建中；预览使用已生成的发布包。正式网站可直接打开同源 HTTPS 地址下的 `/qa.html`。

局域网结果只说明设备能访问这台电脑，**不证明国内公网加载成功**。要确认国内外公网可用性，需在实际发布域名分别测试，并填写所在地区、运营商及 Wi-Fi／移动网络条件。

HTTP 局域网地址没有 Service Worker，不能据此验收离线缓存。离线测试需要正式 HTTPS：先在线加载并确认缓存，再按实际设备方式断网，记录进入与恢复情况。该页不自动断网或清缓存。

## 连续180秒记录

1. 选择“物理设备上实际运行”或对应仿真环境；填写准确机型、系统、浏览器版本和所在网络。无法确认的项目写“未知”。浏览器 UA 不足以验证物理机型，记录会保留用户声明。
2. 等待“场景已就绪”。加载时间从场景文档导航开始，到已有加载界面完成、运行接口可用为止；以100毫秒轮询检测，不能当作第一像素或网络全部空闲时间。
3. 点击“开始180秒实测”。面板自动折叠并把焦点交给场景。保持浏览器前台，不触摸画面；项目执行约105秒的真实游览路线，之后停尾至总计180秒，包含返回起点过渡。
4. 结束时会尝试下载 JSON 初稿。移动浏览器若拦截自动下载，点击“导出当前 JSON”保存。被接管、失焦、切后台、提前停止，或路线没有结束的记录会标为无效完整路线，仍可导出用于诊断。

页面每5秒读取一次已有 `__bjw.metrics()`，开始前调用 `resetMetrics()`；使用 `__dbg.controls.setMode('tour')` 和实际重播接口，未通过定位到离散帧来模拟路线。最终记录帧数、P50/P95帧间隔、资源、质量、分片和地标状态。手机以30 FPS为目标，已确认的 P95 帧间隔验收门槛为 **40毫秒**；33.3毫秒仅为30 FPS理论帧间隔。达标不代表所有人工交互通过。

## 加载字节与缓存

首屏保存场景文档和浏览器暴露的 Resource Timing 条目。正值 `transferSize` 才进入已知传输小计；零值或不可用值输出 `transferSize: null` 和“未测”原因，不能解释为零网络成本。缓存、Service Worker、跨域时间权限和浏览器支持情况都可能造成零值，测试页不会猜测具体原因。

这些数据不是网络抓包，可能遗漏 Worker 或未暴露请求，完整网络字节始终标为未知。编码／解码后的正文大小另列，不能替代实际传输量。冷缓存与热缓存由测试者自行控制并声明；点“重新载入场景”不会清除浏览器或 Service Worker 缓存。

## 人工交互检查与最终导出

连续路线结束后，展开面板选择模式或地标；选择后自动折叠面板并把焦点交给场景，然后直接触控主场景。模式操作点击主产品原有按钮，漫步仍经过附近地面准备流程，不能绕过它直接调用相机切换。依次检查模式切换、游览接管、失焦返回、漫步及连续地标跳转。

每项只有实际操作后才勾选“已测试”，并选择通过／失败／无法完成，补充观察。未勾选的项目输出“未测”，不算失败或通过。记录卡顿、发热、资源失败、触控失灵或网络条件。完成后再次点击“导出当前 JSON”，该文件才包含最终人工结果。

JSON 同时记录 UA、视口、屏幕、现有画布/WebGL信息、用户声明、加载条目、路线采样和中断。还保留 `release.json` 的发布 revision、实际载入的 `city.revision` 和主程序 `bundleURL`，用于定位测试版本。开发环境没有 `release.json` 或无法读取时明确标为不可用；不把当前发布元数据与可能缓存的旧程序自动视为同一版本。部分浏览器隐藏 GPU 信息时会明确留空。结果仅由浏览器下载到设备，没有外部发送或自动汇报。
